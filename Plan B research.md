# **Verdict 1**

SIH26117: Sovereign On-Premise Agentic AI Workbench

Ha problem statement indirectly aplyala **Cluade Code / Codex / Antigravity cha alternative** banvayla sangtoy. Fakt Chating purta lang graph nakoy. Hya system agents sarkha pahije **PDF reading capability**, **file read write capability** (like how antigravity write code directly into .py or .jsx file), **device OCR and Computer Vision**. 

**Very Important Requirement**
Ani tya agent la ek task dila ki toh complete hot nahi to parent iterate zala pahije. Problem Statement Description madhla actual string "iterate on a task instead of answering once and stopping".

**And Challenges**
LLM chi Upper limit 120B parameter model aahe but 7B to 70B parameters che multiple LLM models pahije as available options. Ani hyanchya madhe query **Router use zala pahije (Query Router manjhe toh apla Aqua Router Final Yeat cha project)**.

**Verdict: Not Suitable for Plan B**

Reason: Problem statement sounds easy on paper pan operational complexity khup aahe.

# **Verdict 2**

SIH26122: Intelligent  Infrastructure Project Management: Real-Time Actual Progress Tracking (Planning-to-Execution Bridge)

Ha problem statement basically aplyala field var actual execution madhye kay zala te automatically capture karun existing Primavera/MS Project schedule madhlya correct L5/L6 activity sobat link karayla sangtoy.

Problem mainly AI chatbot banvnyacha nahi. Actual challenge aahe unstructured field data → structured activity → correct schedule activity mapping.

**Very Important Requirement**

System ne **blindly activity match karaychi nahi.** Field language ani schedule language different asu shakto. Tyamule semantic/fuzzy matching + embeddings + business rules use karun candidate L5/L6 activities find karaychya, ani confidence score dyaicha.

But important point mhanje **problem statement itself prototype scope limit karto** — full production OCR/ASR required nahi. Fakt **2–3 input formats + extraction + schedule linking demonstrate** kela tari working prototype sufficient aahe.

Ya problem sathi already khup research available aahe — construction schedule NLP, activity-name normalization, semantic activity matching, daily work report analysis, construction progress monitoring etc.

**Competitor Challenge**

**Problem completely new market create kart nahi.**

Procore, Autodesk Construction Cloud, DatuBIM, Opteam etc. already daily reporting / progress tracking / schedule integration related capabilities provide kartat.

So apan "first AI construction progress tracker" asa claim nahi karu shaknar. So we have to be careful.

**Most Important Advantage**

Ha problem demo karayla comparatively easy aahe but technically meaningful aahe.

Apan synthetic data create karun clear before/after demonstrate karu shakto.

**Verdict: Suitable for Plan B**

Reason: Problem statement initially complex vatla tari actual MVP scope well-defined and manageable aahe. Required **models publicly available** aahet, prototype sathi **high-end compute required nahi** , **synthetic/sample data explicitly allowed** aahe, **research literature strong** aahe, ani **output objectively measure karta yeil** .
